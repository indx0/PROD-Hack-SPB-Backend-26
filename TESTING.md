# Тестирование

## Запуск

Только unit-тесты — Docker и база данных не нужны:

```bash
mvn test
```

Все тесты и свежие отчёты покрытия — нужен запущенный Docker:

```bash
mvn clean verify
```

Интеграционные тесты используют отдельный PostgreSQL в Testcontainers и профиль
`test`. Рабочая база не используется; перед каждым тестом тестовые таблицы очищаются.
При первом запуске Maven скачает зависимости, а Testcontainers — Docker-образы.

В GitLab CI PostgreSQL запускается как отдельный сервис job, без Docker socket
и Docker-in-Docker. Переменная `TEST_DATABASE_EXTERNAL=true` отключает создание
Testcontainers-контейнера; адрес и учётные данные задаются через `TEST_DB_URL`,
`TEST_DB_USERNAME`, `TEST_DB_PASSWORD`. В CI это отдельная одноразовая тестовая БД.
Не направляй эти переменные на рабочую БД: тесты пересоздают и очищают таблицы.
Без `TEST_DATABASE_EXTERNAL=true` локальные тесты по-прежнему используют Testcontainers.

Один unit-класс:

```bash
mvn -Dtest=AuthenticationServiceTest test
```

Один интеграционный класс (unit-тесты тоже выполнятся):

```bash
mvn -Dit.test=RefreshTokenIntegrationTest verify
```

После разделения Surefire/Failsafe команда `mvn test` больше не запускает
интеграционные тесты. Для полного прогона используй именно `verify`, а не
`integration-test`: так Maven проверит результат интеграционных тестов и создаст
общий отчёт покрытия.

## Отчёты

JaCoCo генерирует отдельные HTML/XML-отчёты, без исключения рабочих классов из покрытия:

- Unit: `target/site/jacoco-unit/index.html` и `jacoco.xml` в той же папке.
- Интеграционные: `target/site/jacoco-integration/index.html` и `jacoco.xml`.
- Общий: `target/site/jacoco/index.html` и `jacoco.xml`.

В HTML можно перейти к пакету, классу и строкам кода: видно, что покрыто, а что нет.
Отчёт покрытия не описывает смысл сценариев — для этого служат имена и код
тестовых методов. Для актуального полного набора отчётов запускай `mvn clean verify`.
`mvn test` обновляет только unit-отчёт; старые интеграционные/общие отчёты он не обновляет.

Результаты выполнения (не покрытие) Maven сохраняет в `target/surefire-reports`
для unit и `target/failsafe-reports` для интеграционных тестов. В GitLab они
публикуются во вкладке **Tests** пайплайна. HTML-отчёты JaCoCo можно скачать
в артефактах job **test**, распаковать и открыть соответствующий `index.html`.

## Проекты переездов

`MoveProjectIntegrationTest` проверяет шесть основных сценариев через MockMvc,
настоящие Security/сервисы/репозитории и PostgreSQL, без моков бизнес-логики:

| Сценарий | Что проверяется |
| --- | --- |
| Создание и получение | Владелец из токена, UUID, даты, нормализация и сохранение данных |
| Список | Только свои проекты, пагинация и повторяемый порядок |
| Изменение | Сохранение новых значений, очистка адреса, сохранение пропущенных полей |
| Изоляция пользователей | Чужой проект нельзя читать, изменять или удалять; ответ 404 |
| Удаление | Удаляются все зависимости, содержимое другого проекта сохраняется |
| Валидация | Невалидный запрос возвращает 422 и не создает запись |

Запуск: `mvn -Dit.test=MoveProjectIntegrationTest verify`.
Покрытие этих сценариев включается в интеграционный и общий отчёты JaCoCo.
`MoveProjectControllerTest` отдельно проверяет HTTP-коды и ошибки параметров;
`SecurityIntegrationTest` — авторизацию маршрутов и схемы ответов OpenAPI.

## Общая пагинация

Списки проектов и коробок используют `common.dto.PaginationRequest` и `PageResponse<T>`.
Параметры одинаковые: `page >= 0`, `1 <= size <= 100`, по умолчанию `page=0&size=20`.
Ответ всегда содержит только `content`, `page`, `size`, `totalElements`, `totalPages`;
Spring `Page` используется внутри репозиториев, но не сериализуется в API.
Проекты сортируются по `createdAt DESC, id DESC`, коробки — по `number ASC, id ASC`.
Параметр пользовательской сортировки в Swagger не предлагается.

`PaginationIntegrationTest` проверяет одинаковый JSON-контракт и значения по умолчанию,
границы размера страницы, единый ответ 422 на невалидную пагинацию, пустые страницы,
порядок коробок и фильтрацию с правильными счетчиками. Чужой/несуществующий проект
возвращает 404, собственный проект без коробок — пустую страницу с кодом 200.
Невалидные фильтры коробок также возвращают 422 с `ErrorResponse.fieldErrors`.
`SecurityIntegrationTest` проверяет, что Swagger сохраняет конкретный тип элементов
в обеих специализациях общего `PageResponse<T>`.

Запуск: `mvn -Dit.test=PaginationIntegrationTest verify`.

## Доступ к проектам и ошибки Box

`ProjectAccessService.getOwnedProject(projectId, userId)` — единая проверка владельца
для MoveProject и Box. Отсутствующий и чужой проект возвращают одинаковую ошибку
404 `MOVE_PROJECT_NOT_FOUND`; коробка дополнительно ищется внутри проверенного проекта.
Блокировка коробки при записи сохранена. Проверка доступа не создаёт отдельную
транзакцию при вызове из транзакционного бизнес-метода и сама не блокирует проект.

Ошибки Box обрабатываются через `GlobalExceptionHandler` в формате `ErrorResponse`:
404 `BOX_NOT_FOUND`, 409 `DATA_CONFLICT`, 422 `VALIDATION_ERROR` с `fieldErrors`.
`ProjectAccessServiceTest` проверяет загрузку своего проекта и отказ для чужого/отсутствующего.
`GlobalExceptionHandlerTest` проверяет статусы, коды и обязательные поля ошибок.
Интеграционные тесты MoveProject/Box проверяют доступ через API, отсутствие изменений
при отказе, единый JSON ошибок и сохранение прежней логики удаления/статусов.
Создание Box и смена комнаты проверяют принадлежность комнаты проекту; отсутствующая
или чужая комната возвращает 404 `ROOM_NOT_FOUND`.

`BoxLifecycleIntegrationTest` проверяет создание с начальным статусом PACKING,
уникальность номера внутри проекта, смену комнаты без потери вещей и статуса,
атомарный отказ при конфликте номера и изоляцию комнат разных проектов/пользователей.
События `BOX_CREATED` и `BOX_STATUS_CHANGED` сохраняются в транзакции BoxService.
Повторное чтение не создаёт коробок/событий; повтор статуса не создаёт событие и
не меняет updatedAt. Откат транзакции отменяет одновременно коробку/статус и событие.

Запуск: `mvn -Dit.test=BoxLifecycleIntegrationTest verify`.

## Основа журнала событий

`ProjectEventService.record(...)` сохраняет события через общий репозиторий.
`Propagation.MANDATORY` требует существующую транзакцию бизнес-действия: сервис
не создаёт отдельную транзакцию и не сохраняет событие после отката действия.
Создание проекта записывает `PROJECT_CREATED`; Box использует этот же сервис
для `BOX_CREATED` и `BOX_STATUS_CHANGED`. Автор события берётся из проверенного
пользователя/владельца проекта, а не из тела HTTP-запроса.

`MoveProjectIntegrationTest` проверяет содержимое события создания проекта и
отсутствие события при невалидном запросе. `ProjectEventIntegrationTest` проверяет
запрет записи вне транзакции, совместный откат проекта и события, а также откат
создания проекта/коробки и изменения статуса при ошибке записи журнала.
Для имитации ошибки только в этих сценариях используется spy репозитория;
бизнес-сервисы и транзакции остаются настоящими.

Запуск: `mvn -Dit.test=ProjectEventIntegrationTest,MoveProjectIntegrationTest,BoxLifecycleIntegrationTest verify`.
API чтения журнала: `GET /api/move-projects/{projectId}/events`.

## Комнаты

`RoomIntegrationTest` содержит восемь базовых сценариев через настоящий API-контроллер,
Security, сервисы и PostgreSQL, без моков бизнес-логики:

- Создание, нормализация названия и список с сортировкой/пагинацией.
- Переименование и сохранение значения при пустом или null PATCH.
- Запрет дублей внутри проекта и одинаковые названия в разных проектах.
- Ошибки валидации названия и пагинации без изменения данных.
- Изоляция пользователей/проектов, отсутствующая комната и неверный UUID.
- Удаление пустой комнаты и повторное удаление.
- Запрет удаления комнаты с коробкой; комната, коробка и вещи сохраняются.
- Обязательная авторизация всех четырёх операций.

Запуск: `mvn -Dit.test=RoomIntegrationTest verify`.
Результаты входят в JUnit-отчёт CI и интеграционный/общий отчёты JaCoCo.

## Задачи переезда и шаблоны

`MoveTaskIntegrationTest` содержит десять базовых сценариев через настоящий API,
Security, сервисы и PostgreSQL:

- Создание, нормализация полей и получение карточки без выдачи JPA-сущностей.
- Частичное редактирование и очистка необязательных полей явным null.
- Общая пагинация, сочетание фильтров stage/completed и изоляция проектов.
- Выполнение, повтор отметки без изменения времени/события, отмена и повторное выполнение.
- Список шаблонов с пагинацией, применение, запрет дублей и повторное применение после удаления задачи.
- Единый формат ошибок валидации, JSON, UUID и фильтров без изменения данных.
- Запрет доступа другого пользователя и обращения к задаче через другой проект.
- Удаление только выбранной задачи с сохранением истории выполнения.
- Обязательная авторизация всех восьми операций.
- Идемпотентное заполнение справочника из 11 шаблонов.

`ProjectEventIntegrationTest` дополнительно проверяет откат completedAt, updatedAt
и события при ошибке записи TASK_COMPLETED.

Запуск: `mvn -Dit.test=MoveTaskIntegrationTest,ProjectEventIntegrationTest verify`.

## Завершение плана: первый день, автозаполнение, журнал, демоданные

- `FirstDayChecklistIntegrationTest`: базовые пункты, создание и пагинация, переименование,
  выполнение/отмена и повторы, валидация, удаление, авторизация и изоляция проектов.
- `MoveProjectBootstrapIntegrationTest`: восстановление пустого локального справочника,
  создание 11 задач и 4 пунктов первого дня, сроки в UTC, одно событие создания,
  отсутствие пересчёта/дублей при изменении даты проекта и повторном чтении.
- `ProjectEventIntegrationTest`: ошибка создания чек-листа или записи события откатывает
  проект, задачи и чек-лист целиком. Нет отдельных коммитов начальных данных.
- `MoveWorkflowIntegrationTest`: проект → комнаты → коробка с вещью → перенос → статусы
  до распаковки → выполнение задачи → чек-лист → журнал и статистика. Повторы статусов
  не дублируют события; удаление коробки сохраняет историю. Проверяются также доступ,
  пагинация журнала и событие с необязательным системным автором без выдачи JPA-сущностей.
- `DataLoaderIntegrationTest`: полный демопроект через реальные сервисы, корректные сроки,
  статусы и события, а также повторный запуск без дублей и без смены паролей.
- `SecurityIntegrationTest`: Swagger сохраняет типы элементов общего PageResponse для
  проектов, комнат, коробок, задач, шаблонов, чек-листа и событий.

`MoveTaskIntegrationTest` намеренно очищает автоматически созданные задачи своего
проекта для изолированной проверки собственного CRUD и ручного применения шаблонов.
Автоматический план проверяется отдельными bootstrap- и сквозными тестами.

Запуск новых сценариев: `mvn -Dit.test=FirstDayChecklistIntegrationTest,MoveProjectBootstrapIntegrationTest,MoveWorkflowIntegrationTest,DataLoaderIntegrationTest,ProjectEventIntegrationTest verify`.
Полная проверка, как в CI: `mvn clean verify`. PostgreSQL в тестах отдельная;
никакие тесты не подключаются к рабочей базе ВМ.

Последняя локальная проверка ветки `feature/checklis-logging`: `mvn clean verify`
прошёл (109 unit + 289 integration, без ошибок и пропусков). Дополнительно собранный
JAR запущен в профиле prod на отдельной временной PostgreSQL и loopback-порту:
readiness UP, вход user1, демопроект (12 задач / 6 пунктов / 18 событий), пять статусов
коробок, OpenAPI и создание нового проекта (11 задач / 4 пункта / 1 событие).
Это локальный smoke-test, не подтверждение нового деплоя на ВМ; CI и деплой требуют MR.
