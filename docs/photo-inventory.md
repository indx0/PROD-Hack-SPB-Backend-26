# Опись вещей по фотографии

Сценарий: отправить фото → проверить название и метки → при необходимости исправить → сохранить вещь в коробку.
Можно распознать один главный предмет или получить список вещей. Результат распознавания и фото отдельно не сохраняются.
Фото передаётся внешнему LLM Proxy и провайдеру модели.

## Распознавание

`POST /api/move-projects/{projectId}/ml/item-description`, JWT владельца проекта.
Тело — `multipart/form-data`, ровно один файл `photo`: JPEG, PNG или WebP, до 10 МиБ.
Формат определяется по сигнатуре; расширение и заявленный MIME не влияют на выбор формата.

```bash
curl --max-time 150 \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "photo=@photo.jpg" \
  "http://localhost:8080/api/move-projects/$PROJECT_ID/ml/item-description"
```

Ответ `200`:

```json
{"name":"Белая керамическая кружка","flags":["fragile"]}
```

`name` — до 255 символов. Метки: `fragile` — хрупкое; `first_day` — нужно в первый день;
`carry_personally` — стоит перевозить с собой. Метки — предложение модели, пользователь может их изменить.
Сервер не создаёт вещь при распознавании. Передавать собственный промпт, модель или URL фото через API нельзя.

## Несколько вещей на фото

`POST /api/move-projects/{projectId}/ml/items-description`, JWT владельца проекта.
Запрос принимает ровно один файл `photo` с теми же ограничениями форматов и размера.

```bash
curl --max-time 150 \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -F "photo=@photo.jpg" \
  "http://localhost:8080/api/move-projects/$PROJECT_ID/ml/items-description"
```

Ответ `200`:

```json
{
  "items": [
    {"name": "Белая керамическая кружка", "flags": ["fragile"]},
    {"name": "Белая керамическая кружка", "flags": ["fragile"]},
    {"name": "Зарядное устройство", "flags": ["first_day"]}
  ]
}
```

Возвращается от 1 до 100 предметов в порядке модели. Каждая различимая вещь — отдельный
элемент; одинаковые названия сохраняются, поля количества нет. Модель выбирает уверенно
распознанные предметы, без обещания полноты описи или точного подсчёта.
Если предметов больше 100, промпт просит выбрать до 100 наиболее заметных.
Ответ модели с более чем 100 элементами отклоняется как `502 LLM_INVALID_RESPONSE`, без обрезания.
Один распознанный предмет возвращается списком из одного элемента.
Пустой список или отказ модели — `422 IMAGE_NOT_RECOGNIZED`.
Невалидный элемент (включая пустое название), лишние поля, неправильные метки или
незавершённый JSON делают весь ответ ошибочным: `502 LLM_INVALID_RESPONSE`; частичного результата нет.

Эндпоинт не сохраняет вещи. После проверки можно сохранить каждый выбранный элемент
существующим POST создания вещи. Пакетный ввод names по-прежнему сохраняет только названия.
Маршрут `/item-description` сохраняет прежний контракт одного главного предмета.

## Сохранение и редактирование

Передайте проверенный результат в существующий
`POST /api/move-projects/{projectId}/boxes/{boxId}/items`:

```json
{"name":"Моя белая кружка","flags":["fragile","first_day"]}
```

Ответ `201` — `ItemResponse`, включая `flags`.
Поле доступно также в списках и поиске вещей.
В `PATCH /api/move-projects/{projectId}/boxes/{boxId}/items/{itemId}` поле `flags` полностью заменяет набор:
отсутствие сохраняет текущие метки, `[]` снимает все. `null`, неизвестные метки и повторы запрещены.
Старое создание без `flags` и пакетный ввод `{ "names": [...] }` создают вещи без меток.
Сохранение не вызывает LLM, не меняет статус коробки или `contentsDeferred`.

## Ошибки

Ответы имеют общий формат `ErrorResponse` с `code`, `message`, `traceId`, `time`.

| HTTP | Код | Причина |
| --- | --- | --- |
| 400 | `INVALID_MULTIPART` / `INVALID_PHOTO` / `INVALID_REQUEST_PARAMETER` | Нет photo, несколько файлов, повреждённый запрос или UUID |
| 401 | `UNAUTHORIZED` | Требуется JWT |
| 404 | `MOVE_PROJECT_NOT_FOUND` | Проект отсутствует или недоступен |
| 413 | `IMAGE_TOO_LARGE` | Файл больше 10 МиБ или запрос больше 11 МиБ |
| 415 | `UNSUPPORTED_IMAGE_FORMAT` / `UNSUPPORTED_MEDIA_TYPE` | Неподдерживаемый формат файла или Content-Type запроса |
| 422 | `EMPTY_IMAGE` / `IMAGE_NOT_RECOGNIZED` | Пустой файл, предмет не распознан или модель отказала |
| 502 | `LLM_INVALID_RESPONSE` / `LLM_UPSTREAM_ERROR` | Некорректный/незавершённый ответ или ошибка запроса к прокси |
| 503 | `LLM_UNAVAILABLE` | Нет настройки ключа, сетевая ошибка, квота, ошибка авторизации upstream, upstream 5xx или заняты все обработчики |
| 504 | `LLM_TIMEOUT` | Превышен дедлайн |

Тела ошибок прокси не передаются клиенту и не логируются.

## Настройка и эксплуатация

| Переменная | Значение по умолчанию |
| --- | --- |
| `LLM_PROXY_API_KEY` | Пусто: распознавание возвращает 503, остальные функции работают |
| `LLM_PROXY_URL` | `https://llm-proxy.spirit.t-education.com/chat/completions` |
| `LLM_PROXY_MODEL` | `openai/gpt-6-luna` |
| `LLM_PROXY_CONNECT_TIMEOUT_MS` | `10000` |
| `LLM_PROXY_TIMEOUT_MS` | `120000` |

Единственное имя переменной ключа — `LLM_PROXY_API_KEY`; прежний пример `SPIRIT_AI_KEY` не используется.
Настройки передаются в контейнер через Compose. Ключ хранится только в окружении сервера.
Общий дедлайн охватывает запрос и чтение ответа. Автоматического повторения нет.
Оба маршрута используют общий пул: одновременно выполняется до четырёх обращений на экземпляр приложения, без очереди; перегрузка возвращает 503.
Размер ответа прокси ограничен 64 КиБ.
При увеличении дедлайна согласуйте таймауты клиента и Nginx.

Примените `deploy/nginx.conf` при развёртывании: для обоих маршрутов распознавания заданы
лимит запроса 11 МиБ и `proxy_read_timeout 150s`. Рекомендуемый таймаут клиента — 150 секунд.
Spring ограничивает файл 10 МиБ и запрос 11 МиБ.
В логи попадают только модель, длительность, исход и traceId ошибки; фото, названия и ключ не логируются.
Миграция Liquibase добавляет три boolean-колонки; существующие вещи получают пустые метки.

## Проверка

`./mvnw test` запускает unit-тесты и локальный HTTP-стаб LLM; внешний ключ не требуется.
`./mvnw verify` дополнительно проверяет PostgreSQL через Testcontainers, миграции и сценарий
«фото → проверка → сохранение → чтение».

Для ручной оценки качества используйте собственную тестовую фотографию и эндпоинт либо
`LLM_PROXY_API_KEY=… node ml-tests/describe-item.js <путь-к-фото>`.
Реальный LLM в CI не вызывается.
