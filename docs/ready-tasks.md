# Готовые задачи и начальный чек-лист

Готовая задача — отдельный образец аккаунта. Набор `/api/task-sets` объединяет несколько
таких по смыслу задач, а `/api/move-projects/{projectId}/tasks` содержит реальные задачи
плана. Сохранение образца не создаёт задачу плана и не требует выбранного переезда.

## Каталог отдельных готовых задач (PROD2-188)

Все операции требуют Bearer access-токен.

| Метод и путь | Поведение |
|---|---|
| `GET /api/task-templates` | Общие и свои личные образцы, без удалённых |
| `GET /api/task-templates/{templateId}` | Общий или свой образец |
| `POST /api/task-templates` | Создать личный образец |
| `PUT /api/task-templates/{templateId}` | Полностью заменить свой образец |
| `DELETE /api/task-templates/{templateId}` | Удалить свой образец из каталога, 204 |
| `GET /api/move-projects/{projectId}/tasks/templates` | Тот же доступный каталог с проверкой доступа к проекту |
| `POST /api/move-projects/{projectId}/tasks/from-template` | Явно добавить образец в план доступного активного проекта |

Создание и замена принимают:

```json
{
  "title": "Подготовить переноску",
  "description": "Проверить крепления",
  "stage": "BEFORE_MOVE",
  "dueDateOffsetDays": -2
}
```

`title` обязателен, до 255 символов, пробелы по краям удаляются; одинаковые названия
личных образцов допустимы. `description` необязателен, до 10000 символов; при PUT
отсутствие, null или пробелы очищают описание. `stage` и целое `dueDateOffsetDays`
обязательны: отрицательный срок — до переезда, ноль — в этот день, положительный — после.
Ошибка валидации — 422, некорректный enum/JSON/UUID — 400.

Ответ содержит `id`, эти четыре поля и `personal`: true для своих редактируемых
образцов, false для общих серверных образцов. Общие образцы доступны только для чтения
и применения. GET списка поддерживает `stage`, `page` (от 0), `size` (1–100, по умолчанию 20);
сортировка `title ASC, id ASC`. Фильтр и пагинация выполняются в БД.

Каталог хранится на сервере и возвращается после входа с другого устройства. Чужой UUID,
удалённый образец или попытка изменить общий образец возвращают 404. Участие в общем
переезде не даёт доступа к личным образцам другого участника.

Для применения используйте существующий запрос:

```json
{"templateId": "UUID образца"}
```

Создаётся независимая невыполненная RELATIVE-задача без ответственного, со скопированным
смещением и сроком `дата переезда UTC + dueDateOffsetDays`. Настройки фиксированного срока
и ответственного можно передать по [существующему контракту](task-deadlines.md).
Участник может применить свой образец в общем проекте: остальные увидят созданную задачу.
Пока задача из этого образца существует в проекте, повторное применение возвращает 409.
После удаления задачи образец можно применить заново. Архив запрещает применение (409),
но не работу с личным каталогом.

Изменение образца влияет только на будущие применения. Удаление мягкое (`deletedAt`):
образец скрывается и больше не применяется, прежние задачи, их сроки, выполнение и
ответственные сохраняются. Миграция 0021 сохраняет общие образцы и их UUID, добавляя
необязательного владельца. Откат запрещён, пока есть личные образцы, чтобы не превратить
их в общие и не потерять принадлежность аккаунтам. Порядок блокировок при применении —
проект → образец; редактирование и удаление блокируют образец.

## Выбор первого дня при создании переезда (PROD2-165)

```json
{
  "name": "Переезд",
  "moveDate": "2026-11-15T09:00:00Z",
  "includeFirstDayChecklist": false
}
```

`false` создаёт переезд с пустым чек-листом. `true` или отсутствие поля создаёт ровно
четыре стандартных пункта: зубные щётки, зарядки, чайник, постельное бельё. Явный null — 422.
Выбор применяется в той же транзакции, что проект, участники, выбранные наборы и событие:
ошибка не оставляет частично созданного переезда.

Приложение читает фактическое содержимое через `/api/move-projects/{projectId}/first-day-checklist`.
Обновление страницы, новый вход и повторные GET не создают пункты заново. Существующие
списки и пользовательские пункты не изменяются; имя пункта не используется для удаления.
Параметр независим от `taskSetIds`, меток `firstDay` коробок и вещей.
Обычный POST создания проекта по-прежнему создаёт новый проект при каждом вызове;
общая защита повторного создания из PROD2-117 остаётся отдельной задачей.
