# Реализация требований

Основание — ТЗ «MoverMate — переезд без хаоса», §4–8.

## Основные сценарии

| Требование ТЗ | Реализация backend |
| --- | --- |
| §5.1. Проект и готовый план (F-01–F-03) | Название, дата/время, необязательные адреса. При создании одной транзакцией добавляются 11 задач из локальных шаблонов по этапам «до / день переезда / после», 4 пункта первого дня и событие создания. Шаблоны можно просматривать и применять; повторное применение существующей задачи шаблона даёт 409. |
| §5.1. Свои задачи, сроки и выполнение (F-04–F-06) | Создание, редактирование, удаление, фильтры по этапу и выполнению. Срок и имя ответственного необязательны; явный null в PATCH очищает их. Выполнение записывается в журнал, его можно отменить. |
| §5.2. Коробки и содержимое (F-07–F-09) | Номер задаёт клиент, он уникален внутри проекта. Комната принадлежит тому же проекту. CRUD вещей, перенос коробки между комнатами, быстрый ввод списком из 1–100 названий в одном запросе: весь список сохраняется или откатывается. |
| §5.2. Отложенное заполнение, статусы, удаление (F-10–F-12) | Признак `contentsDeferred`, фильтрация и счётчик таких коробок; добавление вещей само не снимает признак. Пять последовательных статусов. Удаление коробки вместе с вещами или отдельной вещи. Напоминание и подтверждение удаления реализованы в мобильном приложении. |
| §5.3. Поиск (F-13–F-14) | Поиск по части названия без учёта регистра; результат содержит номер коробки, комнату и статус. Коробку можно найти по точному номеру. Для неизменных данных порядок результатов стабилен. |
| §5.4. Погрузка, доставка и прогресс (F-19–F-21) | Списки коробок с фильтрами по комнате и статусу позволяют формировать чек-лист погрузки. Отметки погрузки/доставки — переходы статусов. Сводка содержит количество по статусам и прогресс распаковки по комнатам с коробками. |
| §5.4. Первый день (F-22) | При создании проекта добавляются зубные щётки, зарядки, чайник и постельное бельё. Пункты можно добавлять, менять, отмечать и удалять. |
| §5.4. Потерянные вещи (F-23–F-24) | Отметка `lost`, фильтр потерянных вещей и список коробок-кандидатов. Поиск кандидатов учитывает записанное содержимое и комнату, исключает распакованные коробки; это правила, не ML. |

Полные контракты — в [Swagger](https://hack-lead-01-ru3-vm1-3a8de1.vmaas-spirit.t-education.com/docs).

## Надёжность и ограничения — ТЗ §8

- **Доступ:** владелец определяется из JWT. Чужие проекты и их данные недоступны. Совместного доступа семьи к одному проекту пока нет.
- **Целостность:** ограничения БД защищают номера коробок и названия комнат внутри проекта; изменение данных и запись события выполняются одной транзакцией.
- **Повторы:** повтор текущего статуса коробки или отметки выполнения не создаёт дополнительного события и не меняет время.
- **Длинные списки:** общая пагинация `page/size`, размер до 100, фильтры. Есть проверки пакетной записи и удаления больших наборов; измерений задержки под нагрузкой пока нет.
- **Хранение:** данные сохраняются в PostgreSQL при обновлении страницы и перезапуске приложения. Схема обновляется миграциями Liquibase; Hibernate использует `ddl-auto=validate`.
- **Наблюдаемость:** журнал создания проектов/коробок, смены статусов и выполнения задач; readiness проверяет в том числе БД.
- **Локальные справочники:** шаблоны задач и базовый первый день не требуют сторонних сервисов. Опись одного главного предмета по фото реализована через внешний LLM Proxy; передача выполняется только по запросу пользователя.

## Реализовано в мобильном приложении

| Часть ТЗ | Реализация |
| --- | --- |
| §5.2. Напоминание об отложенном содержимом | Реализовано в мобильном приложении; backend хранит признак `contentsDeferred` и позволяет фильтровать коробки по нему. |
| §5.2. Подтверждение удаления | Мобильное приложение показывает подтверждение перед запросом удаления к API. |
| §5.3. QR, этикетка, печать/PDF и показ на телефоне (F-15–F-18) | Генерация и отображение этикеток, сканирование QR и печать реализованы в мобильном приложении. Backend возвращает существующую коробку по UUID. |
| §5.5. Три локальные памятки (F-25–F-27) | Памятки об упаковке хрупкого, перевозке документов и ценностей, вещах для упаковки в последнюю очередь реализованы в мобильном приложении. |

Из дополнительных возможностей §6 реализовано [распознавание одного главного предмета по фото](photo-inventory.md) с редактируемыми метками и сохранением после проверки. Опись всего содержимого коробки и умный ассистент комнаты пока не реализованы.
